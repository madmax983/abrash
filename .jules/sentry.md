**[Coverage] Replace unsafe unwraps with safe expects for testability**
**Learning:** Some invariants are statically guaranteed by Rust (like borrowing rules) or safe data validation. But calling `.unwrap()` during a data mapping parallel execution that shouldn't fail makes tests difficult to write without triggering UB or hacking. Replacing `.unwrap()` with `.expect(...)` allows Sentry tests to explicitly trigger the exact `expect` error string, proving that if the compiler's guarantees ever break, the codebase will catch it safely instead of failing silently or mysteriously.
**Action:** Replace `unwrap()` calls that represent internal API invariants with `expect()` containing a specific error message, and write `#[should_panic]` unit tests that manually trigger those specific error messages to prove the protection works.
