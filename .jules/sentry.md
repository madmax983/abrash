**[Missing StaleHandle validation in `render_frame_into`]**
**Learning:** We need to explicitly test error propagation paths for `StaleHandle` lookup failures for *every* supported resource type, such as `Mesh` and `Material`. The implementation of `CpuRenderer::render_frame_into` successfully propagated errors internally via `extract_draw_list_into` which validated the handles, but there was a hidden coverage gap because no tests actively triggered and asserted the specific `StaleHandle` errors within this method's bounds.
**Action:** When working on APIs involving multiple resource handles (like `MeshHandle`, `MaterialHandle`), ensure tests are added to verify the failure states for *each* handle independently, preventing hidden coverage gaps where one handle's failure path is tested but others are silently untested.
