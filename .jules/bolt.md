**[Replacing Hot-Path SmallVec with Persistent Vec]**
**Learning:** `smallvec::SmallVec` is excellent for short-lived small collections, but inside tight iteration loops (like sorting bins), if its capacity is exceeded, it silently allocates and deallocates memory on the heap every loop iteration. This can cause massive performance degradation when rendering complex scenes with many overlapping triangles.
**Action:** Replace locally scoped `SmallVec` with a persistent, reusable `Vec` stored on the parent struct (e.g., `sort_buffer: Vec<u32>`). During the loop, extract it using `std::mem::take(&mut self.sort_buffer)` to satisfy the borrow checker, populate it, and place it back at the end of the method. This preserves capacity and ensures absolutely zero allocations on subsequent iterations.
