**Fast Inv Sqrt vs Stdlib SQRT Recip**
**Learning:** Using custom `fast_inv_sqrt` implementations (like the Quake III bit-hack or `_mm_rsqrt_ss` intrinsic) is generally slower and less precise than using the standard library's `.sqrt().recip()` on modern CPU architectures. The standard library automatically leverages hardware-accelerated instructions (like `rsqrtss`) and achieves better performance.
**Action:** Replaced `fast_inv_sqrt(len_sq)` with `len_sq.sqrt().recip()` across the `math`, `quat`, `phong`, `reflection`, and `texture` modules. Also removed the unused `fast_inv_sqrt` function and its associated test. This resulted in improved performance in point light rasterization benchmarks (up to ~17% faster).
