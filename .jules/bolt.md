## 2024-05-18 - `is_fully_on_screen` Boundary Vulnerability
**Learning:** When creating fast-paths that bypass bounds checking (using `unsafe` functions like `set_pixel_unchecked`), the gating condition must validate all inputs meticulously. In circle rasterization, if the radius can be negative, standard bounding box math (e.g. `xc + r`) breaks down because a negative radius shrinks the apparent bounds while the rendering loop still attempts to draw geometry. This allows an out-of-bounds circle to pass the check and trigger Undefined Behavior (OOB memory writes).
**Action:** When calculating bounds checks for geometric primitives using user-supplied parameters (like radius or width/height), explicitly handle negative or invalid inputs at the start of the check block before relying on them in arithmetic.
